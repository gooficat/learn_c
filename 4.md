## What is a function? 

---

A function is an isolated piece of code that can be called. It can take in parameters and output a single value.

A typical function looks like this in Assembly:

```s
my_function:
	push rbp
	mov rbp, rsp
	# [Some code here...]
	pop rbp
	ret
```

You're probably wondering what `rbp` and `rsp` are, and what `push` and `pop` do.

RSP is a special register that *points* to (contains the address of) the top of the stack. The stack is a block of memory given to each program that "grows", with the top of it moving "up" every time you push a value onto it. In reality, it moves toward the lower addresses, i.e. from 0x82000000 to 0x81600000

You can imagine it as a stack of papers. You "push" some paper by placing it on the top of the stack. Then you can "pop" one off by removing it from the top. However, unlike a stack of papers, you can modify and read values from lower parts of the stack.

If you exceed the memory size of the stack by pushing too many values, you get a stack overflow! If you try to pop a value off an empty stack, you get a stack underflow. You may have heard these terms before.

A useful purpose for the stack is for functions. We can create a "stack frame" which is an area of the stack that contains our function's variables for this specific call.

Instead of saying "my variables are at this location in memory", we say "I will claim this amount of bytes starting from wherever the stack pointer currently is, and store my variables there". The benefit of using the stack for variables is that a function can be called inside of itself, or inside of a function that it itself called. This is called "recursion". 

To avoid convoluted code, we also typically use a "base pointer", almost always RBP. This points to the base of our stack frame, meaning its location before we begin pushing and popping values to save them between operations (i.e. when we don't have enough registers to hold it). This means we can always use the same offset relative to rbp, something like ``[rbp - 4]``

When you use the "call" instruction, the instruction pointer is pushed onto the stack, and an unconditional jump is executed. When you use a "ret" (return) instruction, you are popping the value off the stack, back onto the instruction pointer. (Because of this, we must always restore the stack to where it started when we finish a function).

---

The C language is made up entirely of declarations. You are always declaring a variable, function, or label.

Variables in C can have different linkage, storage, base types, and various other flags.

*Linkage* refers to whether a variable is global, static, or local.

A global variable is visible to outside files, as we saw in the previous chapter. In C, we call this *extern linkage*.

A static variable is one visible *only* inside of this file, but throughout the whole file.

A local variable is one that is only visible inside its *scope*. This would be anywhere that is surrounded by curly braces.

Variables not contained in a scope have extern linkage by default. Inside functions, they are local.

*Storage* refers to how the variable is stored in memory. The 3 options are:

- `static`, meaning it exists as a label followed by a number of bytes to contain your variable

- `auto`, meaning it is stored on the stack. It is *automatically* freed upon exiting the scope by restoring the stack pointer.

- `register`, meaning it is stored on a register. Nowadays this one is deprecated, and instead `auto` will put the variable on a register if there is one available.

- `extern`, meaning it comes from somewhere else. This can be outside the file or later on in the file. Either way, it's a forward declaration.

- `inline`, meaning it doesn't exist in the code but a copy is pasted wherever the variable is referenced. This only applies to functions.

- `typedef` is grammatically a storage class, but really is just a way to declare alternative names for a variable type.

Variables not contained in a scope are statically stored by default, and inside functions they are auto by default. If you try to call an undefined function, it is declared extern automatically, but this is limited and not recommended.

As for the actual *type* of the variable, it can be from these base categories:

- `int`. This is a variable that just contains a whole number, which is what we've been working with all this time.

- `float`. This is a special number that holds a rough estimate of a number that may contain decimal parts, like `3.141`.

- `char`. This is a special integer that is one byte long and holds a text character.

- `void`. This is a type that has a width of zero! It's used for saying a function doesn't return anything at all (so doesn't need a register or space on the stack to place its return value), and also used for pointers to unknown values that can be freely cast to other pointer types.

A "pointer" is an address of a variable. You can give an underlying type to a pointer, so as to say "this variable points to another variable which is an integer", for example.

"Casting" is the behaviour of converting between types. Sometimes it is implicit, like passing a char into a function with a parameter that expects an int, and sometimes we do it manually.

On older C versions, variables could be int by default without specifying. Now, it's a bit more explicit and you can't omit all type specifiers.

There are variants of the types we mentioned above

- `long int` is a larger integer, and `long long int` is usually larger still. You can omit the word `int` here and just say `long` or `long long`.

- `short` is usually a shorter int.

- `double` is a double-precision floating point number, and `long double` is at least as precise, sometimes moreso but it depends on the platform.

Note that these are very vague. This is because C is a multi-platform language designed to make it easy to port code to other architectures, so the type specifiers are essentially just hinting.

We can also specify if an integer is `signed` or `unsigned`, which we spoke about earlier. As we said, a signed integer can hold negative and positive values, but an unsigned integer is always positive. This is another case where the word `int` can be omitted.

`char` can also act as an integer but we have to specify the signed-ness because char can have unique behaviour on some platforms.

For our purposes, since we're working with a 64-bit x86_64 system compiled with Clang, our type sizes are:

`char` is 1 byte (8 bits)
`short` is 2 bytes (16 bits)
`int` is 4 bytes (32 bits)
`long` and `long long` are both 8 bytes (64 bits)

All pointers are 8 bytes (64 bits)

However, as you'll see later, we have a more verbose way to specify the size of an integer, through typedefs that come with the C language via a `header file`. We will touch on header files later.
